# 文件清理助手（FileJanitor）详细设计文档

## 一、项目概述

### 1.1 项目背景

日常办公和运维中，经常需要根据一份清单（Excel）批量清理指定目录下的文件或文件夹。手工逐个查找删除效率极低，且容易误删。市面上缺少一款轻量、可视化、安全可控的批量删除工具。本项目旨在开发一款基于 Python 的桌面小工具，通过读取 Excel 中的名称清单，匹配目标路径下的文件或文件夹，并将匹配项安全删除到回收站（可恢复），兼顾效率与安全。

### 1.2 产品定位

一款运行于 Windows 平台的桌面批量清理工具。以 Excel 清单为数据源，以可视化界面为操作入口，以回收站删除为安全保障，帮助用户快速、准确、可追溯地完成批量文件/文件夹清理。

### 1.3 核心价值

| 维度 | 描述 |
| :--- | :--- |
| **批量高效** | 一次读取 Excel 清单，自动匹配并批量删除，替代手工逐个操作 |
| **可视化操作** | 全程图形界面，无需命令行，普通用户即可上手 |
| **安全可控** | 删除前预览、二次确认、删除到回收站可恢复、操作日志可追溯 |
| **灵活配置** | 支持任意列、任意路径、文件/文件夹类型、精确/模糊匹配模式 |
| **轻量便携** | 单文件打包，无需安装 Python 环境，双击即用 |

### 1.4 适用范围

- 批量清理测试环境产生的临时文件夹
- 根据黑名单清单清理指定文件
- 运维场景下按清单清理过期目录
- 个人电脑按清单整理重复文件

**明确不适用**：系统目录清理、需要永久删除（不可恢复）的场景、需要跨网络操作的场景。

## 三、技术选型

| 技术领域 | 选型 | 理由 |
| :--- | :--- | :--- |
| **开发语言** | Python 3.10+ | 生态丰富，开发效率高，跨平台 |
| **GUI 框架** | PySide6 (Qt for Python) | 界面美观现代，组件丰富，支持高DPI，跨平台一致性好 |
| **Excel 读取** | openpyxl | 轻量，不依赖 pandas 等重型库，支持 .xlsx/.xls |
| **回收站删除** | send2trash | 跨平台支持，Windows 下调用系统回收站 API |
| **配置存储** | JSON 文件（`config.json`） | 轻量，易读，无需数据库 |
| **日志** | Python logging + 自定义文件输出 | 标准库，稳定可靠 |
| **打包工具** | PyInstaller | 单文件打包，用户无需安装 Python |
| **线程管理** | `QThread` + 信号槽 | Qt 原生线程机制，避免界面卡顿 |
| **图标资源** | 内置 SVG/PNG | 使用免费图标库（如 Feather Icons） |

**选型说明**：
- 选择 PySide6 而非 tkinter，因为 PySide6 界面更现代美观，且支持表格、进度条、多线程等复杂组件的原生实现。
- 选择 openpyxl 而非 pandas，因为本工具只需读取 Excel 单列数据，openpyxl 更轻量，打包体积更小。
- 选择 send2trash 而非 `os.remove`，因为回收站删除可恢复，是安全保障的核心。

#### 5.1.2 数据清洗规则

| 规则 | 说明 |
| :--- | :--- |
| 去除首尾空格 | `str.strip()` |
| 过滤空值 | 空字符串、`None`、纯空格 全部过滤 |
| 全角转半角 | 可选，默认关闭（避免误伤中文） |
| 统一大小写 | 根据"忽略大小写"设置决定 |
| 去重 | 保留首次出现的值 |
| 长度限制 | 超过 260 字符的条目记录日志并跳过（路径长度限制） |
| 非法字符 | 过滤包含 `<>:"/\|?*` 的条目（Windows 文件名非法字符） |

#### 5.1.3 异常处理

| 异常 | 处理 |
| :--- | :--- |
| 文件不存在 | 提示"文件不存在，请重新选择" |
| 文件被占用 | 提示"文件正被其他程序打开，请关闭后重试" |
| 格式不支持 | 提示"仅支持 .xlsx 和 .xls 格式" |
| 工作表为空 | 提示"该工作表为空" |
| 列无数据 | 提示"该列无有效数据" |
| 读取权限不足 | 提示"无权限读取该文件" |

### 5.2 扫描匹配模块

#### 5.2.1 扫描流程

```
读取待匹配名称列表（Excel数据）
读取目标路径列表
        │
        ▼
┌───────────────────┐
│ 构建匹配索引       │
│ 精确模式：哈希表   │
│ 包含/正则：列表    │
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ 遍历目标路径       │
│ 递归子目录（可选） │
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ 对每个文件/文件夹  │
│ 执行匹配           │
└────────┬──────────┘
         │
         ├── 命中 ──→ 加入结果列表
         │
         └── 未命中 ──→ 跳过
         │
         ▼
┌───────────────────┐
│ 去重（同一路径）   │
│ 排序（按类型/路径）│
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ 返回结果列表       │
└───────────────────┘
```

#### 5.2.2 匹配算法

**精确匹配**（默认）：
将 Excel 名称列表构建为集合（set），遍历文件时直接 `if name in name_set` 判断，时间复杂度 O(1)。忽略大小写时，统一转为小写构建集合。

**包含匹配**：
遍历 Excel 名称列表，判断文件名是否包含任意一个条目。时间复杂度 O(n×m)，但通过预处理可优化。适用于"清单中是关键词，文件名中包含该关键词即匹配"的场景。

**正则匹配**：
将 Excel 名称列表编译为正则表达式列表，遍历时逐个匹配。适用于高级用户。

#### 5.2.3 扫描性能优化

| 优化点 | 说明 |
| :--- | :--- |
| 多线程扫描 | 使用 `QThread` 在后台线程执行，避免界面卡顿 |
| 提前剪枝 | 排除路径提前过滤，不进入 |
| 目录深度限制 | 支持限制递归深度，避免过深目录 |
| 批量匹配 | 精确匹配用集合，O(1) 判断 |
| 进度节流 | 每处理 100 个文件更新一次界面，避免频繁刷新 |
| 中断响应 | 定期检查取消标志，及时响应中断 |

#### 5.3.2 安全检查规则

| 检查项 | 规则 |
| :--- | :--- |
| 系统目录 | 路径包含 `C:\Windows`、`C:\Program Files`、`C:\Program Files (x86)`、`/System`、`/usr`、`/etc` 等，直接跳过 |
| 白名单 | 路径以白名单中的路径为前缀，直接跳过 |
| 路径有效性 | 路径不存在、路径为空、路径为根目录，跳过 |
| 符号链接 | 检测到符号链接时跳过（避免误删链接目标） |
| 正在使用 | 删除失败时捕获异常，记录"文件被占用" |

#### 5.3.3 错误处理

| 错误类型 | 原因 | 处理 |
| :--- | :--- | :--- |
| `PermissionError` | 权限不足 | 记录，继续下一条 |
| `FileNotFoundError` | 文件已不存在 | 记录为"已不存在"，不算失败 |
| `OSError` | 文件被占用 | 记录，继续 |
| `RecursionError` | 路径过深 | 记录，继续 |
| 其他异常 | 未知 | 记录完整堆栈，继续 |

**关键原则**：单条失败不中断整体流程，所有失败项在最终报告中汇总。

## 七、线程与异步设计

### 7.1 线程模型

```
主线程（UI线程）
    │
    ├── 负责界面渲染、用户交互
    │
    ├── 扫描线程（QThread）
    │   ├── 遍历文件系统
    │   ├── 执行匹配
    │   └── 通过信号槽更新UI
    │
    └── 删除线程（QThread）
        ├── 执行 send2trash
        └── 通过信号槽更新UI
```

### 7.2 信号槽设计

| 信号 | 发出者 | 接收者 | 数据 |
| :--- | :--- | :--- | :--- |
| scan_progress | 扫描线程 | 主线程 | 当前路径、已扫描数、已匹配数 |
| scan_item_found | 扫描线程 | 主线程 | 单条匹配结果 |
| scan_finished | 扫描线程 | 主线程 | 结果列表 |
| scan_error | 扫描线程 | 主线程 | 错误信息 |
| delete_progress | 删除线程 | 主线程 | 当前项、已完成数、总数 |
| delete_item_done | 删除线程 | 主线程 | 单条删除结果 |
| delete_finished | 删除线程 | 主线程 | 完成报告 |

### 7.3 界面响应保障

- 所有耗时操作在后台线程执行，主线程永不阻塞
- 进度更新采用节流机制，每 100ms 更新一次，避免频繁刷新
- 支持"取消"操作，通过 `threading.Event` 标志位控制


## 八、安全设计

### 8.1 多层次安全防护

| 层级 | 机制 | 说明 |
| :--- | :--- | :--- |
| **第一层** | Excel 空数据保护 | 读取到 0 条有效数据时禁止扫描 |
| **第二层** | 路径选择保护 | 选择根目录时弹出警告 |
| **第三层** | 系统目录保护 | 硬编码禁止删除系统目录内容 |
| **第四层** | 白名单保护 | 用户可设置永不被删除的路径 |
| **第五层** | 扫描预览 | 删除前必须扫描并预览结果 |
| **第六层** | 手动勾选 | 用户可取消不想删除的条目 |
| **第七层** | 二次确认 | 需勾选"我已确认"才能执行 |
| **第八层** | 回收站删除 | 删除到回收站可恢复 |
| **第九层** | 操作日志 | 全量记录，可追溯 |

### 8.2 系统目录保护清单

以下路径下的内容永不被删除：

| 平台 | 保护路径 |
| :--- | :--- |
| Windows | `C:\Windows`、`C:\Program Files`、`C:\Program Files (x86)`、`C:\ProgramData`、`C:\Users\*\AppData` |
| Linux | `/bin`、`/boot`、`/dev`、`/etc`、`/lib`、`/proc`、`/root`、`/sbin`、`/sys`、`/usr`、`/var` |
| macOS | `/System`、`/Library`、`/Applications`、`/private`、`/usr` |

### 8.3 回收站恢复指引

完成报告中明确提示：
- Windows：打开资源管理器 → 回收站 → 找到对应文件 → 右键还原
- macOS：打开废纸篓 → 找到对应文件 → 右键放回原处
- Linux：打开文件管理器 → 回收站 → 还原

## 十二、风险与应对

| 风险 | 影响 | 应对措施 |

## 十三、总结

本工具以"Excel 清单驱动 + 可视化操作 + 回收站安全保障"为核心设计理念，通过 PySide6 构建现代化界面，openpyxl 实现灵活的 Excel 读取，send2trash 确保删除可恢复。在功能上覆盖数据读取、路径配置、匹配扫描、预览勾选、批量删除、日志报告全流程；在安全上设置九层防护，从数据保护到系统目录保护再到二次确认，最大限度降低误删风险。

工具定位清晰、功能聚焦、操作直观，适合普通办公用户和 IT 运维人员使用。打包后为单文件 exe，双击即用，无需安装 Python 环境，具备良好的分发性和实用性。
